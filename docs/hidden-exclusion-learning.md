# 숨긴 공고의 반복 문구 학습

## 기준

- 같은 유형에서 **서로 다른 유사 공고를 3건 이상 숨김**. 반복 클릭·재수집·새로고침 횟수가 아니다.
- stableId/상세 주소로 숨김 기록을 구별한다. 제목·기관·모집일이 동일한 수집처 중복은 학습에서 한 건으로 계산한다. 별도 모집인지 불분명하면 보수적으로 한 건으로 센다.
- 제목에서 숫자·연도·회차, 대괄호 기관명, 일반적인 모집 표현을 후보에서 제외한다. 구체적인 4자 이상 단어 또는 2~3개 단어의 연속 문구가 공통으로 나타나야 한다. 넓은 분야명(박물관·인턴·학예·문화 등), 기관명·기관 접미어는 학습하지 않는다.
- 같은 세 공고에 여러 문구가 반복되면 더 긴 문구를 택한다. 의미를 이해하는 AI 판정이 아니라 **제목 문구의 보수적인 반복 판정**이다. 다른 표현의 유사 직무는 자동으로 묶이지 않을 수 있다.
- 채용과 직무경험을 구분하고, 직무경험은 인턴/프로젝트/봉사 등 세부 유형까지 같아야 적용한다. 기관명 전체가 아니라 제목에서 단어 경계가 맞는 실제 문구를 검사한다.
- 수동 `noise-keywords.txt` → 학습한 제외 문구 → 자격·분야·적합도 평가 순서. 학습 규칙이 수동 제외를 해제하지 않는다.

## 예시

제목이 `[A기관] 특수장비검사관 1차 모집`, `[B기관] 특수장비검사관 2차 모집`, `[C기관] 특수장비검사관 3차 모집`인 세 채용을 숨기면 `특수장비검사관`이 채용 유형의 제외 문구가 된다. 이는 설명용 예시이며 실제 수집 데이터에 넣지 않는다.

세 건 모두 `특수장비검사관 원격탐사`라는 더 구체적인 문구를 공유하면 그 문구만 학습한다. 단순히 세 건에 `박물관 인턴 모집`이 들어간다는 이유로 박물관·인턴 전체를 제외하지 않는다.

## 사용법과 서버 반영

1. 페이지의 **숨김 학습·제외 규칙**을 펼쳐 문구, 유형, 건수, 세 제목 근거를 확인한다. 규칙은 이 브라우저 목록에 즉시 적용한다. 즐겨찾기 사본·스케줄러는 자동 삭제하지 않는다.
2. 오탐이면 **규칙 해제**. 공고를 복원하면 그 공고가 학습 건수에서 빠진다. 3건 미만이 되면 로컬 규칙이 사라진다. 서버에 이미 반영한 규칙은 다음 단계로 다시 내보내 제거해야 한다.
3. **제외 규칙 내보내기**로 JSON을 다운로드한다. 서버에는 자동 전달되지 않는다. 다른 브라우저의 별도 숨김 기록은 합산되지 않는다.
4. Work-Finder 폴더에서 실행한다. 내보낸 파일의 실제 경로를 입력한다.

```powershell
Set-Location 'C:\Users\namkyu-gu\workspace\Work-Finder'
npm run exclusions:import -- 'C:\Users\namkyu-gu\Downloads\work-finder-exclusions-2026-09-28.json'
```

가져오기는 검증 후 `data/learned-exclusions.json`을 **교체**한다. 삭제·해제를 반영하기 위해 병합하지 않는다. 이전 파일은 `data/learned-exclusions.json.previous.local`에 보관한다. 그 파일은 Git에서 제외된다. 오류 파일은 기존 규칙을 변경하지 않는다.

5. 로컬 다음 수집부터 적용된다. GitHub 예약 수집과 Discord 알림에 반영하려면 변경된 `data/learned-exclusions.json`을 커밋·푸시한다. 예약 시각까지 기다리거나 Actions에서 기존 워크플로를 수동 실행한다. 토큰을 웹페이지에 넣는 방식은 사용하지 않는다.

저장소가 공개이면 커밋한 문구와 세 제목 근거도 공개된다. 내보내기에는 숨김 전체 기록·즐겨찾기·URL·Discord 비밀값을 포함하지 않는다.

## 기존 기록과 보존

기존 `wf_hidden_postings`의 제목/소스 키를 새 `wf_hidden_learning_v1`에 이전한다. 현재 공고와 연결되면 유형을 확인해 학습에 포함한다. 소스 장애·종료로 현재 공고가 없는 기록은 제목을 보존하되 유형을 추측해 제외 규칙으로 만들지 않는다. 다시 수집되면 연결한다. 저장 실패·손상은 경고하고 기존 저장소를 덮어쓰지 않는다.

서버는 제외 규칙 파일을 읽거나 검증하지 못하면 명시적으로 실패한다. 현재/이전 수집 결과 모두에 동일한 제외 규칙을 적용해 규칙 변경을 가짜 신규·마감 알림으로 보내지 않는다.

## 버튼

원문 열기·즐겨찾기·숨기기는 모두 **112×40 CSS px**. 즐겨찾기 등록/해제, 숨김/복원 상태와 PC·모바일에서 동일하다.
