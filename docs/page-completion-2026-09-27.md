# 페이지 구성 이행 보완 — 2026-09-27

## 확인된 미구현 원인

이전 버전에는 직무경험 유형 이름은 있었지만 실제 수집기는 봉사 소스 3개뿐이었다. 화면 배지도 소스별로 봉사/알림을 고정 표시했다. 직무경험 실행기는 제외어 필터를 우회했다.
즐겨찾기는 `siteId::title` 문자열만 저장해 현재 목록에서 사라진 공고의 본문·일정을 잃었다. 달력은 현재 월에서 시작하며 기존 일정 배열이 있으면 마감일 필드를 병합하지 않았다. 등록일을 접수 시작으로 추정하는 처리도 있었다.

## 적용한 화면 구성

| 화면 | 동작 |
|---|---|
| 채용공고 | 기존 검색·신규·기간·기관·숨김 유지. 제외어 → 지원불가 신호 → 관련성 → 정렬 순서. 단순 전시와 채용기준 사전공개도 모집으로 노출하지 않음 |
| 직무경험 | 기본은 **자원봉사 제외 모집 공고**. 유형별 건수와 필터 제공. 인턴/프로젝트/일경험/교육/상담/비용지원 등을 같은 하위 분류에서 관리 |
| 사업 안내 | 직무경험 안의 별도 선택. 사업 대상·운영기간·공식 모집 안내 링크 표시. 접수기간 미확인이므로 모집 중이라고 주장하지 않음 |
| 즐겨찾기 | 안정 ID와 공고 사본 저장. 목록 누락/제목 변경/마감 후에도 보존. 추천에서 제외된 저장물은 그 사실을 경고 |
| 스케줄러 | 접수·활동·사전교육 기본 표시, 등록일은 선택 사항. 가까운 향후 일정이 있는 월로 진입. 월과 무관한 향후 일정 목록, 일정 미확인 목록, 하루 3건 초과 펼치기 |
| 수집 상태 | 화면 하단에 소스별 수집량·노출대상 수·실패·오래된 데이터·상세 날짜 누락. 분석 결과 급감 경보도 표시 |

별표 버튼은 `즐겨찾기 / 저장됨` 문구와 `aria-pressed`를 함께 제공한다. 로컬 저장 실패를 사용자에게 알리고 기존 손상 데이터는 덮어쓰지 않는다. JSON 내보내기/가져오기로 브라우저·기기 간 수동 이동이 가능하다. 자동 서버 동기화는 아니다.

## 실제 연결한 비봉사 소스

- 고용24 청년일경험 포털: 공개 프로그램 목록의 전체 페이지와 공식 총 건수를 대조한다. 인턴형·프로젝트형·ESG/일경험을 저장하고 모집기간, 사전직무교육, 일경험기간을 구분한다. 상세 화면은 GET 주소만으로 공고가 열리지 않아 공식 읽기용 POST 폼을 사용한다. 알림의 링크는 해당 제목 검색 결과로 연결한다.
- 경기일자리재단 청년사업: 사업 소개 목록 및 상세의 대상·운영기간·신청 안내 링크를 수집한다. 모집 회차의 공고가 확인되지 않으면 `program_info`로 둔다.
- 모든 소스에 제외 키워드 파일을 먼저 적용한다. 고용24 일반 제조업 등은 자동 목표분야로 올리지 않는다. 수도권 사무·행정은 인접분야로 별도 표시하며 학예경력 인정이나 본인의 지원자격 충족을 보장하지 않는다.

최상위 구조는 채용과 직무경험 둘을 유지한다. 유형이 존재한다는 것과 실제 모집 데이터가 확보되었다는 것을 구분하며, 없는 유형은 0건을 표시한다.

## 날짜·이력 규칙

- 등록일은 접수 시작일이 아니다. 명시된 모집/접수/신청기간과 활동/봉사/일경험기간만 읽는다.
- 연도가 없는 날짜는 현재 연도를 추측하지 않는다. 구체 날짜로 확인되지 않은 사업 운영 월은 달력에 넣지 않는다.
- 고용24의 단축 연도와 기간 끝의 연도 생략을 처리하되 불명확한 연도 넘김은 미확인으로 남긴다.
- 기존 일정 배열과 날짜 필드를 병합한다. 이전 버전의 `inferred` 접수 시작 이벤트는 달력에서 제외한다.
- 상세 날짜 보강은 소스당 최대 12건·35초의 제한이 있다. 읽기 실패는 `detailStatus=failed`, 첨부·동적 본문 등에서 날짜를 찾지 못하면 `detailWarning`을 기록한다. 1365는 이 과정으로 실제 모집·봉사기간을 확보했다.
- 즐겨찾기는 마지막 확인값을 사본으로 저장한다. 새 수집에서 날짜가 빠졌으면 이전값 보존임을 표시하며, 확정 연장일을 받으면 갱신한다. 알 수 없는 레거시 키도 삭제하지 않고 연결 대기 목록에 둔다.
- 목록에서 사라진 것만으로 종료라고 단정하지 않는다. `missing`으로 구분하고 신규 모집 알림에서 제외한다.
- 반복 프로그램의 모집 관찰 월에는 명시적 접수 시작일만 쓴다. 수집한 월을 모집 월로 꾸며 넣지 않는다.

## 정리한 코드

- `web/index.html`: 구조·기존 스타일. 기존 거대 인라인 스크립트를 제거했다.
- `web/app.js`: 채용/직무경험 공통 카드, 검색·필터·탭·달력·저장소 동작.
- `web/model.js`: 날짜 병합·안정 ID·즐겨찾기 마이그레이션·사본 동기화 등 순수 함수.
- `web/app.css`: 새 구성과 버튼·모바일 보완.
- `crawlers/schedule.ts`, `detail-dates.ts`: 날짜 처리와 제한된 상세 수집 공통화.
- `scripts/prepare-web.mjs`, `serve.mjs`: Windows에서도 직무경험/상태 JSON을 빠뜨리지 않는 로컬 실행.
- 채용/직무경험 수집의 타임아웃 타이머 및 브라우저 컨텍스트 종료 정리.
- `deduplicate.ts`: 제목 토큰 10자만 겹쳐도 다른 기관의 공고를 삭제하던 퍼지 중복 제거를 없앴다. 같은 소스의 공식 ID 또는 URL·기관·제목·기간이 같은 확정 중복만 제거한다. 출처별 이력·상태 집계를 위해 다른 소스의 사본은 유지한다.

## 저장 데이터와 검증

- `data/experience-sources.json`: 소스 범위, 노출 규칙, 아직 수집하지 않는 범위.
- `data/program-catalog.json`: 실제 수집한 사업 안내 상세 사본. 전체 직무경험 수집 때 갱신.
- `crawlers/experience-results.json`: 모집+사업 안내, 날짜 근거, 분류, 상세 상태.
- `crawlers/results.json`, `source-health.json`, `notification-summary.json`: 기존 파이프라인 유지.
- `data/history/*.jsonl`, `opportunity-state.json`, `program-series.json`: 기존 누적 기록 유지.
- `npm test`: 제외어·관련성·날짜·사본/이전 즐겨찾기 회귀 검사.
- `npm run typecheck`: 타입 검사.
- `npm run test:ui`: 실제 수집 JSON으로 유형 표시, 봉사 기본 제외, 즐겨찾기 저장 및 원본 누락 보존, 달력, 사업 안내, 모바일 가로 넘침, 스크립트 오류 검사. `.test-artifacts/`에 화면 저장.

## 실행

```text
npm run crawl
npm run crawl:experience
npm run analyze
npm run serve
```

기존 GitHub Actions 오전 6시/오후 6시 일정과 Discord 비밀 설정은 유지한다. 테스트를 배포 전 단계에 추가하고 상태 JSON도 배포한다. 비봉사 인접 직무경험의 변경은 일일 요약 P3에 포함한다. 새 소스 첫 수집은 기준선이므로 모든 항목을 신규로 알리지 않는다.

## 남는 범위 — 완료로 표시하지 않은 것

고용24의 모든 훈련과정/전국 상담사업을 수집하는 것은 아직 아니다. 이미지·첨부 HWP/PDF의 OCR, 지원자 개인 조건과 필수요건의 완전 대조도 미구현이다. 박람회 독립 수집기, 반복사업 자동 사전예고, 서버 기반 즐겨찾기 동기화는 별도 단계다. 이 부분은 현재 소스와 데이터를 명시해 공고가 없는 것과 수집하지 않는 것을 구분한다.
