# 수집 실패·공고 감소 수정 (2026-09-28)

## 원인과 재확인

기간 미설정 22→14, 1주 이내 14→6을 실제 사용자 화면에서 확인했다. 수집 실패, 날짜 경계 오류, 정상 종료/비모집 제외, 개인 숨김이 섞여 있었으며 기간 조건만으로 전체 감소를 설명할 수 없다.

최신 실패 실행 36365376360이 이전 정상 실행 36364659952의 문화품앗이 6건·1365 5건을 빈 결과로 덮어썼다. 채용도 국가유산청 두 피드·나라일터에서 실패가 발생했다. 이전 실행의 성공 상태가 이후 실행의 성공을 보장하지 않는다.

앞선 진단의 연구원 두 공고는 **누락으로 확정하면 안 된다**. 본문 재확인 결과 사무원 공고(bbs_idx=48368)는 09-16~09-18, 부여 부소산성 공고(bbs_idx=48355)는 09-08~09-11 접수였다. 현재 목록에서 제외하는 것이 정상이다. 마감일 확인 결과 때문에 수집 결과 자체에서 제거된 것을 단순 페이지 누락과 혼동했다.

## 구현

- `resilience.ts`: 시도 결과와 마지막 정상 캐시를 분리. 실패는 error·시도시각을 유지하고, 이전 공고에 `verificationStatus=retained`와 원래 `lastConfirmedAt`을 남긴다. 부분 결과는 이번 확인값 우선, 나머지는 이전 확인값 보존. 연속 실패해도 원래 확인시각은 늘리지 않는다. 정상 0건은 과거 데이터로 덮지 않으며 상태 경보를 낸다.
- 마지막 정상 파일을 Actions 캐시·아카이브에 포함. 기존 캐시가 이미 실패 값으로 덮인 경우를 위해 여섯 소스의 이전 정상 아카이브를 초기 복구 데이터로 저장. 출처는 `data/source-recovery-provenance.json`. 이후 더 최신 정상값과 정상 0건이 항상 우선한다. 토큰·서명 URL은 저장하지 않는다.
- 문화품앗이·1365 검색/이동에서 제출 전에 실제 문서 이동 대기를 등록. 초 단위 고정 대기로 이동 완료를 추측하지 않는다. 첫 연결은 제한된 재시도. 실패 페이지/지역 앞의 결과는 `PartialCrawlError`로 보존한다. 나라일터에도 같은 이동 대기와 부분 결과 보존 적용.
- 연구원/소속기관 두 목록의 각 3페이지를 수집. 실제 두 번째 공개 페이지 함수가 없는 `pageindex2` 필드를 참조하므로, 관찰한 읽기 전용 검색 폼의 실제 `pageindex` 필드로 제출한다. 사이트에 데이터 등록을 하는 폼은 아니다.
- 상세 날짜 보강 한도를 합격자 공지·비대상 직무에 낭비하지 않도록 후보 선정 개선. 상세 실패/누락 시 이전 확정 일정은 `retainedSchedule` 경고와 함께 보존한다. 명시적인 새로운 마감일은 최신값 우선.
- 오래된 공고 판정을 한국 날짜로 통일. 확인된 미래 마감일/상시/모집중 표시의 장기 공고는 유지. 오래된 마감 미상은 기본 정리 기준을 유지하고 별도 “오래된·모집 여부 미확인 공고도 보기” 체크로 열람. 확인된 마감은 이 체크로도 표시하지 않는다.
- 마감일 없는 실패 보존 공고는 마지막 확인 후 7일이 지나면 기본 목록에서 제외하고 검토 보기·캐시에만 보존한다. 확인된 미래 마감일은 해당 마감일까지 유지한다. 모두 현재 모집 확정이 아닌 이전 증거라고 표시한다.
- UI는 실패 자료를 일괄 버리지 않으며, 목록 위 경고·공고별 이전값 표시·실패 수집처 버튼·빈 목록의 실패 설명을 제공한다. 정상 미수집과 실패를 구분한다.
- 분석·Discord: 보존 자료는 신규/변경/긴급 공고로 보내지 않고 관측 횟수·마지막 확인일·반복사업 패턴을 늘리지 않는다. 소스 경보는 이번 확인량과 보존량을 분리한다. 이전 일정만으로 긴급 알림을 보내지 않는다. 즐겨찾기 확인시각도 보존 자료로 갱신하지 않는다.
- 제외 키워드 최우선, 숨김 학습/개인 숨김, 지원 불가/비대상/후속 공지 필터, 즐겨찾기·일정·동일 버튼 크기를 유지한다. 사용자의 실제 브라우저 저장 기록은 변경하지 않는다.
